  to `src/mapmaker`; retained the old tree pending a content audit.
- Initially added a project-local MapMaker setup helper. Environment setup was

- The profile uses non-ADL `bbcbasic.bin`. BBC BASIC starts correctly, and
  MapMaker runs when entered manually at its prompt with:

  ```basic
  LOAD"MAPMAKER.BAS"
  RUN
  ```

- Confirmed the working automatic startup sequence. MOS must load the
  interpreter image while `/bin` is current, then change to MapMaker's
  directory before transferring control with `RUN`:

  ```text
  SET KEYBOARD 1
  cd /bin
  load bbcbasic.bin
  cd /mapmaker
  RUN . MAPMAKER.BBC
  ```

  Directly invoking `bbcbasic.bin` starts its interactive prompt, so later
  autoexec lines are not processed as intended.

## Centralized game variables and save-state groundwork

- Added `src/asm/vars.asm` as the canonical home for mutable game variables,
  reserving `state.asm` for future formal state-machine code.
- Moved player state, room visitation flags, random-generator seeds, active
  sprite-table bookkeeping, and the current BJ health image out of their
  former owning modules without changing any public symbol names.
- Divided the new module into explicit regions:

  - a contiguous 66-byte durable scalar save record;
  - an 84-byte runtime-only workspace containing derived values, calculation
    scratch, and absolute timers which must be reset or rebased on restore;
  - a four-byte debug-only region which is deliberately outside the save-file
    contract and is used at the Author's sanity's peril.

- Documented that a complete saved game must also serialize the active 8 KiB
  room image at `cell_status` and the valid 8 KiB visited-room backing images
  selected by `room_flags` and `room_dat_lut`. These images contain mutable map
  cells, pickups, enemies, and sprite records.
- Left unresolved save-state candidates as follow-up comments in `vars.asm`
  instead of guessing about their authority or restoration behavior. Key
  possession and floor-completion state do not yet appear to have canonical
  global storage.
- The initial variable relocation was validated in the emulator. The final
  layout, including authoritative sprite bookkeeping and the explicit debug
  section, assembles successfully to the same 28,774-byte executable size.
