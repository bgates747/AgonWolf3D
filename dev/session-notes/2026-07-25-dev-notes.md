## Centralized game variables and save-state groundwork

- Added `src/asm/vars.asm` as the canonical home for mutable game variables,
  reserving `state.asm` for future formal state-machine code.
- Moved player state, room visitation flags, random-generator seeds, active
  sprite-table bookkeeping, and the current BJ health image out of their
  former owning modules without changing any public symbol names.
- Divided the new module into explicit regions:

  - a contiguous 66-byte durable scalar save record;
  - an 84-byte runtime-only workspace containing derived values, calculation
    scratch, and absolute timers which must be reset or rebased on restore;
  - a four-byte debug-only region which is deliberately outside the save-file
    contract and is used at the Author's sanity's peril.

- Documented that a complete saved game must also serialize the active 8 KiB
  room image at `cell_status` and the valid 8 KiB visited-room backing images
  selected by `room_flags` and `room_dat_lut`. These images contain mutable map
  cells, pickups, enemies, and sprite records.
- Left unresolved save-state candidates as follow-up comments in `vars.asm`
  instead of guessing about their authority or restoration behavior. Key
  possession and floor-completion state do not yet appear to have canonical
  global storage.
- The initial variable relocation was validated in the emulator. The final
  layout, including authoritative sprite bookkeeping and the explicit debug
  section, assembles successfully to the same 28,774-byte executable size.

## Map design and runtime manual

- Began a living manual under `docs/map-design-manual`, linked from the
  top-level README and the project handoff notebook. It gives map Authors a
  process-first path through floor planning, MapMaker authoring, building,
  deployment, and feature testing, while keeping binary formats, generated
  records, runtime state, and coding constraints in appendices.
- Established **floor**, **map room**, and **chamber** as distinct terms and
  documented the non-obvious authoring contracts: begin from the valid
  `blank` map rather than MapMaker's ID-1 Clear state, use dense floor/room
  IDs, place exactly one start in room 0, pair every room link with one unique
  reciprocal link, and keep each room at or below 64 sprite objects.
- Traced the map pipeline from five-byte BBC BASIC records through stages 06,
  07, and 91c into the external 8 KiB runtime room image. Recorded the exact
  cell, visibility-mask, and sprite-table layouts, plus generated-table
  assumptions and current validation gaps.
- Cross-checked the running behavior of every active object class against the
  assembly. The manual distinguishes implemented room links, pickups,
  scenery, enemies, and mutable-room restoration from incomplete regular
  doors, keys, triggers, and next-floor movement.
- Recorded an existing restart hazard discovered during the trace:
  `plyr_restart` does not clear `room_transition_active`, so a death while
  still on an arrival-door cell can leave a stale reverse-transition vector
  armed at the room-0 start. No application code was changed in this
  documentation pass.
- Documented assembly extension points for floor transitions, functional
  doors, keys, build validation, saved games, future 16×16 authoring, sprite
  catalog coupling, and the planned separation of `maps.asm`
  responsibilities.
- Added Author-agenda task 30: map generation must reject any map room with
  more than 64 sprite-rendered cells and identify the offending floor, room,
  count, and limit.
- Added Author-agenda task 31: map generation must reject gaps in the
  zero-based floor sequence or in any floor's zero-based map-room sequence
  before emitting direct-indexed pointer tables.
- Added Author-agenda task 32: `plyr_restart` must clear the active
  room-transition state so death on an arrival-door cell cannot leave a stale
  reverse-transition vector armed at the floor start.
- Reorganized the manual's planning review into build-enforced invariants and
  designer-discretion checks. Added Author-agenda task 33 for exactly one

- Corrected the MapMaker authoring guidance: map rooms no longer require
