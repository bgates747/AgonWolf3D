## Current operational sequence

   `images.inc`.

## Loose-file performance baseline

A large set of real game PNG assets was imported into the ignored AGNB source
directory and processed at native dimensions with the new
`make_unscaled_images.py` workflow. The resulting loose-file application built,
ran correctly in the isolated emulator, and then ran successfully on physical
Agon hardware after deployment to the real SD card. Image loading was extremely
slow and comparable to the original game workload, giving us a credible
reproduction of the problem. Since the video application has already
demonstrated that sequential image data can be streamed to the VDP at roughly
15 or more frames per second on average, repeated MOS/FatFS filename lookup and
file-open work in a directory containing hundreds of assets is the leading
suspected bottleneck. The planned AGNB comparison will retain this loose-file
application as the control and replace hundreds of named-file operations with
one container open followed by sequential metadata and payload reads.
